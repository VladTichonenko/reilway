# 🔐 Настройка сессии WhatsApp на Railway

## Проблема
На Railway каждый раз появляется QR-код для авторизации, хотя локально сессия уже сохранена.

## Решение: Персистентное хранилище

Railway нужно настроить так, чтобы сессия сохранялась между перезапусками.

### Вариант 1: Railway Volume (Рекомендуется)

1. В Railway Dashboard откройте ваш проект
2. Перейдите в **Settings** → **Volumes**
3. Создайте новый Volume:
   - **Mount Path**: `/app/.wwebjs_auth`
   - **Name**: `whatsapp-session`

4. В настройках сервиса добавьте переменную окружения:
   - `SESSION_PATH=/app/.wwebjs_auth`

### Вариант 2: Экспорт/Импорт сессии с локальной машины

#### Шаг 1: Экспорт сессии с локальной машины

```bash
# На вашей локальной машине
# Создайте архив папки с сессией
tar -czf whatsapp-session.tar.gz .wwebjs_auth/
```

#### Шаг 2: Импорт на Railway

1. В Railway Dashboard откройте ваш проект
2. Перейдите в **Settings** → **Volumes**
3. Создайте Volume (как в Варианте 1)
4. Подключитесь к контейнеру через Railway CLI:
   ```bash
   railway run bash
   ```
5. Загрузите архив (через Railway CLI или через веб-интерфейс)
6. Распакуйте:
   ```bash
   cd /app
   tar -xzf whatsapp-session.tar.gz
   ```

### Вариант 3: Использование переменной окружения

Если у вас уже есть сохраненная сессия, можно загрузить её через переменную окружения:

1. Закодируйте папку `.wwebjs_auth` в base64:
   ```bash
   tar -czf - .wwebjs_auth/ | base64 > session.txt
   ```

2. Добавьте содержимое `session.txt` в Railway как переменную окружения `SESSION_DATA`

3. В коде добавьте распаковку при старте (но это сложнее)

## Рекомендация

**Используйте Вариант 1 (Railway Volume)** - это самый простой и надежный способ.

После настройки Volume:
1. Первый запуск - отсканируйте QR-код
2. Сессия сохранится в Volume
3. При следующих перезапусках QR-код не понадобится

## Проверка

После настройки проверьте логи:
- Должно быть: `📁 Путь к сессии: /app/.wwebjs_auth`
- Если сессия найдена, QR-код не появится
- Если сессии нет, появится QR-код (отсканируйте один раз)
