# 🚂 Инструкция по деплою на Railway

## Проблемы и решения

### Проблема 1: Отсутствие системных библиотек
При деплое на Railway возникала ошибка:
```
Error: Failed to launch the browser process: Code: 127
libglib-2.0.so.0: cannot open shared object file: No such file or directory
```
**Решение:** Dockerfile устанавливает все необходимые системные библиотеки.

### Проблема 2: SIGTERM при запуске
```
npm error signal SIGTERM
```
**Решение:** 
- Приложение теперь использует переменную `PORT` от Railway
- HTTP сервер запускается ДО инициализации WhatsApp клиента
- Добавлен healthcheck endpoint на `/`

### Проблема 3: Runtime.callFunctionOn timed out (бот падает через день при простое)
При длительном простое на Railway CDP-вызовы к браузеру начинают таймаутиться:
```
Runtime.callFunctionOn timed out. Increase the 'protocolTimeout' setting...
```
**Решение:**
- В конфиг Puppeteer добавлен `protocolTimeout` (по умолчанию 3 мин). При необходимости задайте `PROTOCOL_TIMEOUT_MS` в переменных окружения (мс).
- При нескольких подряд таймаутах polling бот автоматически вызывает переподключение (`reconnectClient`), чтобы оживить сессию без перезапуска контейнера.

### Проблема 4: Контейнер останавливается через день
```
Stopping Container
npm error signal SIGTERM
```
**Причина:** Railway может перезапускать контейнеры по разным причинам:
- Отсутствие обработки сигнала SIGTERM (Railway отправляет SIGTERM при остановке)
- Idle timeout (отсутствие активности)
- Проблемы с graceful shutdown (некорректное завершение процессов)

**Решение:**
- ✅ Добавлена обработка SIGTERM и SIGINT для graceful shutdown
- ✅ Все интервалы и таймеры отслеживаются и корректно очищаются при завершении
- ✅ Добавлен keep-alive механизм (периодические запросы к healthcheck)
- ✅ Улучшен healthcheck endpoint (`/` и `/health`) с информацией о состоянии
- ✅ HTTP сервер корректно закрывается при завершении
- ✅ WhatsApp клиент безопасно закрывается с таймаутом

## Решение
Создан `Dockerfile`, который устанавливает все необходимые системные зависимости.

## Шаги для деплоя:

### 1. Убедитесь, что файлы созданы:
- ✅ `Dockerfile` - установка зависимостей
- ✅ `.dockerignore` - исключение ненужных файлов

### 2. Настройка в Railway:

#### Вариант A: Через GitHub (рекомендуется)
1. Подключите ваш репозиторий к Railway
2. Railway автоматически обнаружит `Dockerfile`
3. Нажмите "Deploy"

#### Вариант B: Через Railway CLI
```bash
railway login
railway init
railway up
```

### 3. Настройка переменных окружения в Railway:
В настройках проекта Railway добавьте:
- `SERVER_URL` - URL вашего основного сервера (если используется)
- `PORT` - Railway автоматически устанавливает этот порт (не нужно настраивать вручную)
- `BOT_PORT` - опционально, если нужно использовать конкретный порт (по умолчанию используется PORT)
- `PROTOCOL_TIMEOUT_MS` - опционально, таймаут CDP в мс (по умолчанию 180000 = 3 мин). Увеличивает устойчивость при простое (избегает "Runtime.callFunctionOn timed out")

### 4. Настройка персистентного хранилища для сессии:
**ВАЖНО:** Чтобы не сканировать QR-код каждый раз, настройте Volume:

1. В Railway Dashboard: **Settings** → **Volumes**
2. Создайте Volume:
   - **Mount Path**: `/app/.wwebjs_auth`
   - **Name**: `whatsapp-session`
3. Добавьте переменную окружения (опционально):
   - `SESSION_PATH=/app/.wwebjs_auth`

Подробнее см. `RAILWAY_SESSION.md`

### 5. После деплоя:
1. Проверьте логи в Railway - должен появиться QR-код (только первый раз)
2. Отсканируйте QR-код для авторизации WhatsApp
3. После авторизации сессия сохранится в Volume
4. При следующих перезапусках QR-код не понадобится

## Что делает Dockerfile:
- Устанавливает Node.js 18
- Устанавливает все системные библиотеки, необходимые для Chrome/Puppeteer
- Копирует и устанавливает зависимости проекта
- Запускает приложение

## Примечания:
- Первый деплой может занять больше времени из-за установки зависимостей
- После деплоя нужно будет отсканировать QR-код для авторизации
- Сессия WhatsApp сохраняется в `.wwebjs_auth` (персистентное хранилище в Railway)
- Keep-alive механизм автоматически поддерживает активность сервиса
- Graceful shutdown обеспечивает корректное завершение всех процессов при перезапуске

## Если проблемы остаются:
1. Проверьте логи в Railway Dashboard
2. Убедитесь, что все переменные окружения установлены
3. Попробуйте пересобрать проект (Rebuild в Railway)
